>栈是一块预先规定的SRAM，有编译器生成的代码自动管理：函数调用时往下生长，返回时弹回。它的大小在启动文件里写死，没有硬件保护，用完就是踩内存。
# 现象
```c
static int add(int a, int b)
{
    int sum = a + b;
    return sum;
}

int main(void)
{
    int x = 1;
    int z = add(x, 2);
    return z;
}
```
在`-O0`情况下编译，进Debug，分别在`add`内部和`main`调用之后暂停，看Watch窗口里的地址：
- `&x` 在高地址，`&a`、`&b`、`&sum` 都比它低；
- `add` 执行期间，Register 窗口里的 SP 值比 `main` 里小；
- 未初始化的 `z` 在赋值前是个说不清来路的值，每次复位重跑可能还不一样。
三个问题：
+ 栈帧里到底有什么、地址为什么是这个顺序
+ SP是谁在拨动、按什么规则
+ 那块内存为什么是脏的
# 栈在物理上是什么
+ STM32上，栈是SRAM最高处的一块区域，边界由三样东西定死：
```asm
Stack_Size      EQU     0x00000400      ; 栈的总预算，1KB
Area    STACK, NOINIT, READWRITE, ALIGN=3
        SPACE   Stack_Size              ; 在 SRAM 里占住 1KB，进 ZI-Data
```
## 栈的位置
+ 链接时，链接器按布局规则把所有段依次放进 SRAM（0x20000000 起，共 20KB，到 0x20005000 止（F103C8T6为例）
+ 链接器把 `__initial_sp` 解析成 0x20005000，填进向量表的第一个字——也就是 Flash 的 `0x08000000` 处
```text
0x20000000  ┌─────────────┐
            │ .data       │  有初值的全局变量
0x20000020  ├─────────────┤
            │ .bss        │  零初始化全局变量
0x20000080  ├─────────────┤
            │ HEAP        │  512B（Heap_Size EQU 0x200）
0x20000480  ├─────────────┤
            │ STACK       │  1024B（Stack_Size EQU 0x400）
0x20005000  └─────────────┘  ← SRAM 结束
```
+ 栈顶：SRAM末尾，复位时由硬件装载
+ 栈底：STACK段的低地址端，没有标记，没有保护
+ 越界之后：往下是HEAP、.bss,写过去不报任何错
>“栈向低地址生长”的具体含义：每压入数据，SP减小；每次弹出数据，SP增大。SP永远指向当前栈的有效数据（Cortex-M 是 full-descending 栈，SP 指向最后压入的那个字）
## 硬件在复位时装载SP
任何程序生效前先执行:
1. 从`0x00000000`（被映射到Flash的`0x08000000`,Boot0=0时)读一个32位的字->装进SP
2. 从地址 `0x00000004` 读一个 32 位的字 → **装进 PC**，开始执行。
>第 1 步读到的就是刚才链接器填的 0x20005000
>第 2 步读到的是 `Reset_Handler` 的地址
```text
//时间线
上电 → 硬件读 0x08000000 → SP = 0x20005000（栈就绪了！）
     → 硬件读 0x08000004 → PC = Reset_Handler
     → 执行 Reset_Handler 第一条指令
     → ... SystemInit → __main（复制 .data、清零 .bss）→ main
```
## SP由指令拨动
假设当前SP=0x20005000，执行`PUSH{R7,LR}`
```text
执行前:  SP = 0x20005000

动作:    SP 先减 8        → 0x20004FF8
         r7 写到 0x20004FF8-0x20004FFB
         lr 写到 0x20004FFC-0x20004FFF
//注意最高存到0x20004FFF，因为0x20005000不是可写的区域，它是边界
执行后:  SP = 0x20004FF8
```
>注意PUSH{R7,LR}是一个动作，先计算SP，然后从新SP开始，按寄存器编号**从低到高**依次存储
>对应的 `POP {R7, PC}` 是逆操作：从 `[SP]` 和 `[SP+4]` 把值取回来，SP 加 8
## 满递减
+ full-descending
+ 递减：每存一个字，SP先变小，数据写在SP指的地方，用一次少一块
+ 满：SP的值本身就是”最后一个已存数据“的地址，所以 `SP = 0x20004FF8` 时，`[SP]` 读到的就是 r7 的值
# 一次函数调用的完整过程
以 `main` 调用 `add(x, 2)` 为例，把 `-O0` 下 AC6 生成的代码逐步走一遍（指令是真实形态，具体编码以反汇编为准）
**调用之前**，`main` 要把参数准备好。AAPCS[^1] 规定前四个参数走寄存器：
```asm
MOVS R0,#1 ;x->参数a
MOVS R1,#2 ;2->参数b
BL add ;把返回地址写进LR链接寄存器，然后跳转。此时栈还没有动
```
进入add：
```asm
PUSH {R7,LR} ;保存帧指针和返回地址，SP-=8
SUB SP,SP,#0x10 ;给局部变量腾16字节，SP-=16
ADD R7,SP,#0 ;R7=当前的帧基准
```
+ LR必须压栈，因为add之后如果再调用别的函数，BL会覆盖LR；哪怕不调用，`PUSH {r7, lr}` 也是 `-O0` 的固定套路，宁可多压
+ `SUB SP,SP,#0x10`腾出的16字节放a、b、sum
>为什么是16字节，a、b、sum总共不是12字节吗？
>这是因为AAPCS要求“在函数入口的公共接口处，SP必须是8字节对齐的，需要向上取8的倍数
+ R7是帧指针，指向本帧的固定基准，之后所有局部变量都用[R7,#偏移]访问---SP在函数中段还可能会动，R7不会
```text
//此时的栈
高地址
+---------------------------+
|  main 的局部变量 (x, z)    |
+---------------------------+
|  返回 main 的地址 (lr)      |  ← PUSH {r7, lr} 压入
+---------------------------+
|  保存的 r7                  |
+---------------------------+
|  a 的副本 | b 的副本 | sum  |  ← SUB SP, #0x10
+---------------------------+  ← SP
//add所有的局部变量地址都比main的低，因为它的整个帧压在main的帧下面
```
函数返回：
```asm
ADDS R0，... ;返回值放R0（代码略）
ADD SP,SP,#0x10
POP {R7,PC}
```
+ `POP {r7, pc}` 一条指令完成“恢复现场 + 返回”。SP 回到进函数时的值，`pc` 回到 `main` 里 `BL` 的下一条。`sum` 的内存没有清零，只是不再属于任何变量。
+ 超过四个参数时，第五个及以后的参数由调用在`BL`之前压栈，被调用函数用`[sp,#偏移]取`；返回后由调用者负责回收（被调用者不清理）。所以“参数多一个，调用者的栈帧就大一点”，而帧大小记在调用者头上
+ 对齐规则：AAPCS要求“在函数入口的公共接口处，SP必须是8字节对齐的”
	+ PUSH偶数个寄存器正好保持对齐
	+ 局部变量总大小凑不成8的倍数时，编译器会补齐
# AACPS
+ 四参数以内最省：参数全程走寄存器，栈帧里没有参数位置；从第5个参数开始存入栈中，调用者的帧开始变大
+ **返回值超过 64 位**（结构体返回）：r0/r1 装不下，改为调用者传一块内存的指针进来（隐藏的第一个参数），被调用者往里写
# MSP、PSP和RTOS
Cortex-M有两个栈指针
+ MSP(主栈指针)：复位后默认使用，裸机程序全程用它，中断一定用它
+ PSP(进程栈指针)：RTOS上下文切换后任务使用，每个任务有自己的任务栈
>裸机上所有代码和所有中断共享一个栈
>FreeRTOS下任务栈大小是xTaskCreate的参数，中断仍然用MSP
# 脏数据
```c
void f(void)
{
    int a;              /* a 是多少？ */
}
```
a的诞生只是`SUB SP,#4`,没有任何人往那4个字节写过数据。那块内存上一次被使用，是之前某一个函数的栈帧--内容就是它的残留
>未初始化的全局变量在.bss段，启动代码时整段清0；
>局部变量在栈上，没有人管

************
[^1]:AACPS：**（ARM Architecture Procedure Call Standard）是ARM架构的“函数调用契约”**。它规定了函数之间如何传递参数、如何返回值、哪些寄存器必须保护、栈必须如何对齐等。它的根本目的，是让**分别编译的代码（C、汇编、不同的库）能够正确地互相调用**

	|寄存器|AAPCS 角色|调用时的规则|
	|---|---|---|
	|R0 - R3|参数 / 返回值 / 临时寄存器|**调用者保存（Caller-saved）**。函数可以随意覆盖，调用者若需保留原值，必须在调用前自己压栈。|
	|R4 - R11|变量寄存器|**被调用者保存（Callee-saved）**。被调用的函数如果要用它们，必须先压栈保存，返回前恢复原值。|
	|R12 (IP)|过程间调用临时寄存器|调用者保存，专供链接器在生成跳转代码时临时使用。|
	|R13 (SP)|栈指针|必须始终指向有效的栈内存。在**公共接口**（如C函数边界）处，AArch32要求**8字节对齐**|
	|R14 (LR)|链接寄存器|保存函数返回地址。如果函数内部还要调用其他函数，需先将LR压栈。|
	|R15 (PC)|程序计数器|指向当前指令|

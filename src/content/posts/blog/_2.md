# 机制
## 三个纬度
| 维度   | 回答的问题      | 取值           | 决定时间              |
| ---- | ---------- | ------------ | ----------------- |
| 存储期  | 对象活多久      | 静态、自动、动态、线程  | 编译期（前两种）、运行期（后两种） |
| 作用域  | 名字在哪可见     | 块、文件、函数原型、函数 | 编译期，纯词法           |
| 链接属性 | 跨文件是否同一个对象 | 无、内部、外部      | 编译期 + 链接期         |
### 组合
| 组合 | 例子 |
| --- | --- |
| 静态存储期 + 块作用域 + 无链接 | 函数内 static int x; |
| 静态存储期 + 文件作用域 + 内部链接 | 文件作用域 static int g; |
| 静态存储期 + 文件作用域 + 外部链接 | 文件作用域 int g; |
| 自动存储期 + 块作用域 + 无链接 | 函数内 int a; |
| 动态存储期 | malloc 返回的对象，没有作用域概念 |
| 静态存储期 + 块作用域 + 外部链接 | 块内 extern int g;，名字作用域在块内，对象在别处 |
## 存储期
+ 静态存储期：对象在程序启动前创建，程序结束后销毁，初值只设置一次
	+ 文件作用域的变量（无论有没有`static`）
	+ **函数内**的`static`变量
	+ 字符串字面量
+ 自动存储期：进入块时创建，离开块时销毁。C不保证它落在栈上，只保证存储期；实现可以放在寄存器
	+ 块作用域内
	+ 没有`static`也没有`extern`的变量
	+ 函数参数
+ 动态存储期：由free结束
	+ malloc，calloc，realloc
+ 线程存储期
## 作用域
+ 块作用域：`{}`内声明的名字，从声明处到块结束
+ 文件作用域：在所有函数外声明的名字，从声明处到翻译单元[^1]结束
+ 函数原型作用域：原型里的参数名，出了原型就失效
+ 函数作用域：`goto`的标签，整个函数可见
```c
void f(void) {
    goto label;   // 可以跳到后面
    {
        label:    // 标签写在块内
        ;
    }
    // 这里仍然可以 goto label
}
```
+ 作用域是纯编译期的概念，跟对象活多久无关
## 链接属性
+ 无链接：
	+ 块作用域内没有`extern`的变量
	+ 函数参数
	+ typedef名字
+ 内部链接：
	+ 文件作用域内用`static`声明的对象和函数，只在本翻译单元可见
+ 外部链接：
	+ 文件作用域内没有`static`的对象和函数
	+ 块内`extern`声明的对象
	+ 所有翻译单元的同名外部符号在链接时合并成一个
+ 函数的默认链接属性时外部链接
外部链接这里要注意：
1.链接属性：回答两个翻译单元的的符号是不是同一个符号
2.定义规则：这个符号能有几个定义
```c
/*
*实验一：两个定义
*两个都是外部链接，是同一个符号，但是翻译单元结束时都变成0初始化的外部定义，链接时冲突
*/
//a.c
int x;
//b.c
int x;
/*
*实验二：一个定义+若干声明
*两个都是外部链接，是同一个符号，但是只有一个定义，两个x引用同一块存储
*/
//a.c
int x;         //外部链接，定义
//b.c
extern int x;  //外部链接，声明，不产生定义```
# static,extern,const
## static的两幅面孔
### 块内static
+ 修改存储期
```c
void f(void)
{
    static int n = 0;   // 静态 + 块 + 无链接
    n++;
}
```
+ n从自动存储期变成静态存储期，从栈搬到全局区。作用域和链接属性不变
### 文件作用域static
+ 修改链接属性
```c
static int g=1;//全局变量，静态+文件+内部链接
```
+ static将g的链接属性由外部变成内部
+ static对**函数**同样修改为**内部链接**属性

| 写法 | 存储期 | 作用域 | 链接属性 | 典型段 |
| --- | --- | --- | --- | --- |
| 文件作用域 int g; | 静态 | 文件 | 外部 | .bss |
| 文件作用域 int g = 1; | 静态 | 文件 | 外部 | .data |
| 文件作用域 static int g; | 静态 | 文件 | 内部 | .bss |
| 文件作用域 static int g = 1; | 静态 | 文件 | 内部 | .data |
| 块内 int a; | 自动 | 块 | 无 | 栈/寄存器 |
| 块内 static int x = 1; | 静态 | 块 | 无 | .data |
| 块内 extern int g; | 由定义决定 | 块 | 外部 | 由定义决定 |
| 文件作用域 static void f(void) | — | 文件 | 内部 | .text |
>static定义的函数仍然存储在.text段，不会因为由static定义就变到.data或.bss
## extern
```c
extern int g;           // 声明，不分配存储
extern int g;           // 可以重复声明
int g = 1;              // 定义，只能有一次
```
- `extern int g;` 是声明。整个程序没有定义时，链接报 undefined symbol。
- `extern int g = 1;` 是定义。标准允许，但容易误导，不写。
- 块内 `extern int g;` 引用的是外部链接的对象，不是局部变量。
- `extern int a[];` 是合法的不完整类型声明，定义时要给出大小
## const
+ C和C++在这里相反
```c
// C：文件作用域 const 是外部链接
const int table_size = 10;

```cpp
// C++：文件作用域 const 是内部链接
const int table_size = 10;
```
+ 所以 C 的头文件里写 `const int N = 10;`，被多个翻译单元包含时，可能触发 multiple definition
+ *如果这个常量只被用作数组长度，编译器可能把它折叠成立即数、根本不生成对象，错误就不出现。换个用法或换个优化等级，问题才冒出来*
# MCU
+ 函数内的`static`变量永远占SRAM
+ **函数内 `static` 让函数不可重入。** 主循环和中断都调用它，状态会被打断
+ **中断和主循环共享的变量要 `volatile`。** 编译器可能把它缓存在寄存器里；`volatile` 只保证真的读写，不保证原子性
+ **头文件里的 `static` 变量每个翻译单元一份。** 三个 `.c` 包含就三份，RAM 乘三
+ **启动早期不能依赖 `.data` 的初值。** `SystemInit` 在 `__main` 之前运行，而 `__main` 才负责复制 `.data`、清零 `.bss`。在 `SystemInit` 里读有初值的全局变量，读到的是 SRAM 残留值

**********
[^1]:翻译单元(translation uint)：一个`.c`源文件经过预处理之后的完整产物
	编译器编译的单位不是“文件”，而是翻译单元
	可以简单的认为：
	a.c + 它 include 的所有头文件展开后 = 翻译单元 1
	b.c + 它 include 的所有头文件展开后 = 翻译单元 2
	几个.c就是几个翻译单元，每个头文件被若干个.c包含，就被复制进几个翻译单元

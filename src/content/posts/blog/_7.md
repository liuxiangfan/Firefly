>复位之后，CPU 执行的第一条指令不是 `main`，甚至不是任何一行 C 代码。在 `main` 之前，有一段汇编和一段 C 库代码在干活：它们设置栈指针、搬运 `.data`、清零 `.bss`、初始化 C 库、调用构造函数，最后才把控制权交给 `main`
```text
时间线
上电/复位
  ↓
硬件取向量：MSP ← [0x00000000]，PC ← [0x00000004]
  ↓
Reset_Handler（汇编启动代码）
  ↓
SystemInit()（芯片级初始化）
  ↓
__main（C 库入口，编译器运行时提供）
  ├── __scatterload：搬 .data，清 .bss
  ├── 调用 __cpp_initialize__aeabi_ 遍历 .init_array（C++ 全局构造）
  └── 进入 __rt_entry
        ├── 初始化堆栈（__user_setup_stackheap）
        └── 调用 main()
```
# 第一阶段：上电/复位--硬件取向量
```asm
Stack_Size      EQU     0x00000400 ;栈大小是1KB
                AREA    STACK, NOINIT, READWRITE, ALIGN=3 ;定义名为STACK的段，不初始化清零，可读可写，按8字节对齐
Stack_Mem       SPACE   Stack_Size;在当前端预留Stack_Size个字节，标签Stack_Mem指向这块区域的起始地址
__initial_sp;栈顶指针初始值标签，链接器会把它放在这块栈区域的末尾

                AREA    RESET, DATA, READONLY
__Vectors       DCD     __initial_sp               ; Top of Stack
                DCD     Reset_Handler              ; Reset Handler
                DCD     NMI_Handler
                ...
```
+ `STACK` 段标 `NOINIT`，只占 RAM 地址；`__initial_sp` 是链接器算出的栈顶地址（`Stack_Mem + Stack_Size`）。
+ Cortex-M内核复位后，硬件直接做两件事，**不经过任何软件**
	1. 从地址`0x00000000`读取第一个32为字，装入主栈指针MSP
	2. 从地址`0x00000004`读取第二个32位字，装入程序计数器PC（即复位向量）
+ 栈指针在“栈还没有建好”之前就已经有了初值--这个值不是代码算出来的，而是链接器把 `__initial_sp` 符号的地址写死在向量表的第 0 项里
+ `SystemInit()` 作为一个 C 函数之所以能正常调用，正是因为这个硬件机制已经给 MSP 赋了有效地址
+ **此时的内存状态**：MSP已经有了有效值；PC即将指向`Reset_Handler`;`.data`未复制，`.bss`未清零
>为什么向量表必须在Flash的最前面呢？
# 第二阶段：Reset_Handler--汇编启动代码
```asm
Reset_Handler    PROC
                 EXPORT  Reset_Handler             [WEAK]
        IMPORT  SystemInit
        IMPORT  __main

                 LDR     R0, =SystemInit
                 BLX     R0
                 LDR     R0, =__main
                 BX      R0
                 ENDP
```
+ PC被填成复位向量后，CPU从该地址开始执行，这就是`Reset_Handler`。它位于启动文件中，是复位后的第一段软件代码
+ `Reset_Handler`通常做几件事：
	+ 软件再次设置SP（硬件已经设过，但是汇编里可能显式重设，确保栈顶安全）
	+ 调用`SysytemInit()`--`BLX R0`
	+ 跳转到`_main()`--`BX R0`,不返回
+ **内存状态**：`.data/.bss`仍无效，所以`SystemInit`里不能用依赖初值的全局变量
>1.为什么`SystemInit`里不能用依赖初值的全局变量?
>	**`SystemInit` 执行时，`__main` 里的 `__scatterload` 还没跑——`.data` 的运行区还没从 Flash 复制过来，`.bss` 还没清零。此时读带初值的全局变量读到的是 RAM 里的随机值，写进去的值随后又会被 `__scatterload` 覆盖掉**
# 第三阶段：SystemInit--芯片级初始化
+ 启动文件里只有`BLX R0`触发它，函数体在`system_stm32f4xx.c`
## 函数整体结构
```c
void SystemInit(void)
{
  /* 1. FPU 设置 */
  #if (__FPU_PRESENT == 1) && (__FPU_USED == 1)
    SCB->CPACR |= ((3UL << 10*2)|(3UL << 11*2));
  #endif

  /* 2. RCC 复位到默认状态 */
  RCC->CR |= (uint32_t)0x00000001;
  RCC->CFGR = 0x00000000;
  RCC->CR &= (uint32_t)0xFEF6FFFF;
  RCC->PLLCFGR = 0x24003010;
  RCC->CR &= (uint32_t)0xFFFBFFFF;
  RCC->CIR = 0x00000000;

  /* 3. 可选：外部存储器控制器 */
  #if defined(DATA_IN_ExtSRAM) || defined(DATA_IN_ExtSDRAM)
    SystemInit_ExtMemCtl();
  #endif

  /* 4. 配系统时钟 */
  SetSysClock();

  /* 5. 向量表重定位 */
  #ifdef VECT_TAB_SRAM
    SCB->VTOR = SRAM_BASE | VECT_TAB_OFFSET;
  #else
    SCB->VTOR = FLASH_BASE | VECT_TAB_OFFSET;
  #endif
}
```
## 第1步：FPU设置--必须最先做
```c
#if (__FPU_PRESENT == 1) && (__FPU_USED == 1)
    SCB->CPACR |= ((3UL << 10*2)|(3UL << 11*2));
#endif
```
+ Cortex-M4F 的协处理器访问控制寄存器 `CPACR` 默认禁止访问 CP10/CP11（即 FPU）。`(3UL << 10*2)` 和 `(3UL << 11*2)` 分别把 CP10、CP11 设成“全访问”。
>为什么要放在最前面呢？
> 一旦后续代码里有浮点指令，编译器生成VFP指令（ARM传统硬件浮点扩展）前CPACR必须已开，否则报错
## 第2步：RCC恢复到默认状态
```c
RCC->CR |= (uint32_t)0x00000001;      // HSION = 1
RCC->CFGR = 0x00000000;               // SW=HSI，分频全 1
RCC->CR &= (uint32_t)0xFEF6FFFF;      // 清 HSEON(16)、CSSON(19)、PLLON(24)
RCC->PLLCFGR = 0x24003010;            // PLLCFGR 复位值
RCC->CR &= (uint32_t)0xFFFBFFFF;      // 清 HSEBYP(18)
RCC->CIR = 0x00000000;                // 关所有 RCC 中断
```
+ 目的：把RCC恢复到默认状态，抹掉bootloader、上次运行、调试器可能留下的时钟配置

| 操作                     | 作用                                                            |
| ---------------------- | ------------------------------------------------------------- |
| CR \|=0x1              | 确保 HSI 开（复位后本来开，再确保一次）                                        |
| `CFGR = 0`             | SW=HSI，AHB/APB 分频全 1，暂时跑在 HSI 16MHz                           |
| `CR &= 0xFEF6FFFF`     | bit16 HSEON=0、bit19 CSSON=0、bit24 PLLON=0，关 HSE、关时钟安全系统、关 PLL |
| `PLLCFGR = 0x24003010` | 写回复位值，清掉旧 PLL 参数                                              |
| `CR &= 0xFFFBFFFF`     | bit18 HSEBYP=0，清 HSE 旁路                                       |
| `CIR = 0`              | 关 RCC 中断                                                      |
>注意CFGR=0把系统时钟切回HSI，但是代码没有等待SWS确认，因为下一步`SetSysClock`会重新配PLL并再次切换，这里只是先把状态清理干净
## 第3步：可选的外部存储器控制器
```c
#if defined(DATA_IN_ExtSRAM) || defined(DATA_IN_ExtSDRAM)
  SystemInit_ExtMemCtl();
#endif
```
+ 默认工程里这段不编译,需要将宏取消注释
+ 如果启用，`SystemInit_ExtMemCtl` 会配 FMC/FSMC 和 GPIO，把外部 SRAM/SDRAM 初始化好，供 `.data`/堆/栈使用。**它必须在 `SetSysClock` 之前**，因为外部存储器访问依赖正确的时钟和 GPIO 复用配置。

## 第4步：SetSysClock--F401分支用HSI驱动PLL
```c
static void SetSysClock(void)
{
#if defined(STM32F401xx)
  __IO uint32_t StartUpCounter = 0, HSIStatus = 0;

  /* ① 使能 HSI 并等待就绪 */
  RCC->CR |= ((uint32_t)RCC_CR_HSION);
  do {
    HSIStatus = RCC->CR & RCC_CR_HSIRDY;
    StartUpCounter++;
  } while((HSIStatus == 0) && (StartUpCounter != HSE_STARTUP_TIMEOUT));

  if ((RCC->CR & RCC_CR_HSIRDY) != RESET)
    HSIStatus = 0x01;
  else
    HSIStatus = 0x00;

  if (HSIStatus == 0x01)
  {
    /* ② 调压器 Scale 1 */
    RCC->APB1ENR |= RCC_APB1ENR_PWREN;
    PWR->CR |= PWR_CR_VOS;

    /* ③ 总线分频 */
    RCC->CFGR |= RCC_CFGR_HPRE_DIV1;    // HCLK = SYSCLK / 1
    RCC->CFGR |= RCC_CFGR_PPRE2_DIV1;   // PCLK2 = HCLK / 1
    RCC->CFGR |= RCC_CFGR_PPRE1_DIV2;   // PCLK1 = HCLK / 2

    /* ④ 配 PLL：源=HSI，M=16，N=336，P=4，Q=7 */
    RCC->PLLCFGR = PLL_M | (PLL_N << 6) | (((PLL_P >> 1) -1) << 16) |
                   (RCC_PLLCFGR_PLLSRC_HSI) | (PLL_Q << 24);

    /* ⑤ 使能 PLL 并等待锁定 */
    RCC->CR |= RCC_CR_PLLON;
    while((RCC->CR & RCC_CR_PLLRDY) == 0) {}

    /* ⑥ 配 Flash 等待周期 */
    FLASH->ACR = FLASH_ACR_PRFTEN | FLASH_ACR_ICEN | FLASH_ACR_DCEN
               | FLASH_ACR_LATENCY_2WS;

    /* ⑦ 切换系统时钟到 PLL 并等待确认 */
    RCC->CFGR &= (uint32_t)((uint32_t)~(RCC_CFGR_SW));
    RCC->CFGR |= RCC_CFGR_SW_PLL;
    while ((RCC->CFGR & (uint32_t)RCC_CFGR_SWS) != RCC_CFGR_SWS_PLL) {}
  }
  else
  {
    /* HSI 起不来：什么都不做，继续跑 HSI */
  }
#else
  /* 其他型号：原版 ST 代码，HSE 驱动 PLL */
  ...
#endif
}
```

## 第5步：向量表重定位
```c
#ifdef VECT_TAB_SRAM
  SCB->VTOR = SRAM_BASE | VECT_TAB_OFFSET;
#else
  SCB->VTOR = FLASH_BASE | VECT_TAB_OFFSET;
#endif
```
+ 默认 `VECT_TAB_SRAM` 被注释、`VECT_TAB_OFFSET = 0x00`
+ 注意时序：硬件复位时已经从`0x00000000`取过MSP和复位向量了，这里写VTOR不是给复位用的，而是给后续中断用的。
+ 复位后 VTOR 默认是 0，如果这里不写，中断向量表仍指向 0 地址（Flash 别名区），在默认布局下也能工作；但一旦有 bootloader 或向量表偏移，就必须显式设 VTOR。
# 第四阶段：\_mian--C库运行时初始化
+ 启动文件没有`_main`的函数体，`Reset_Handler` 的 `BX R0` 把控制权交给它。但启动文件末尾为它的**堆栈初始化子步骤**提供了符号
>`_main`的函数体并不存在于我们的项目源代码中，它位于ARM Compiler提供的C库里，是在链接阶段由链接器自动加入到最终的可执行文件中
>C库是静态库，按需拉取
```asm
                 IF      :DEF:__MICROLIB
                 EXPORT  __initial_sp
                 EXPORT  __heap_base
                 EXPORT  __heap_limit
                 ELSE
                 IMPORT  __use_two_region_memory
                 EXPORT  __user_initial_stackheap
__user_initial_stackheap
                 LDR     R0, =  Heap_Mem
                 LDR     R1, =(Stack_Mem + Stack_Size)
                 LDR     R2, = (Heap_Mem +  Heap_Size)
                 LDR     R3, = Stack_Mem
                 BX      LR
                 ENDIF
```
## 4.1 \_scatterload：搬.data\清.bss
- `__scatterload_copy`：把 `.data` 初值从 Flash 复制到 RAM 运行区；
- `__scatterload_zeroinit`：把 `.bss` 清零
## 4.2 .init_array：C++全局构造
+ `__cpp_initialize__aeabi_` 遍历 `.init_array`，调用注册的构造函数。纯 C 工程通常为空，机制仍在。
## 4.3 \_\_rt_entry：堆栈初始化
这里才用到启动文件末尾导出的符号：
- **MicroLIB 路径**：链接时定义 `__MICROLIB`，导出 `__initial_sp`、`__heap_base`、`__heap_limit`，库直接使用；
- **标准库路径**：导出 `__user_initial_stackheap`，`__rt_entry` 调用它，从 `R0–R3` 取堆基址、栈顶、堆顶、栈底，按两区域模型建立堆管理。
>MicroLIB和标准库路径的区别：
>定义MicroLIB：
>	ResetHandler跳转\_main的简化版入口
>	MicroLIB的\_main直接使用导出的`__initial_sp`、`__heap_base`、`__heap_limit` 等符号建立堆和栈
>	不会执行`.init_array`中的C++全局构造函数
>	初始化流程更短，启动速度更快
>不定义MicroLIB（标准库）：
>	Reset Handler跳转\_main的完整库入口
>	导出的是 `__user_initial_stackheap` 函数
>	标准库的 `__rt_entry` 会调用这个 `__user_initial_stackheap` 函数，从 `R0-R3` 寄存器获取堆和栈的边界信息，从而建立运行时环境
>	这个过程**会**处理 `.init_array`，调用所有 C++ 全局构造函数
>	此外，还会进行更完整的库初始化，以确保 `printf`、`malloc` 等标准函数的行为符合 ISO C 规范
# 4.4 调用main()
+ **此时内存状态：** `.data` 已复制、`.bss` 已清零、堆栈边界已建立、C++ 全局对象已构造。

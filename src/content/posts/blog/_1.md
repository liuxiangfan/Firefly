	- 前两种真的没占内存吗？
	- 第三种为什么留下来了，第四种为什么反而消失？
	- Code 多出来的 32 字节，是把数组初始化一遍的代码吗？
+ 答案分别是：不一定；因为链接器按“段”决定去留，而不是按“变量”；不是，静态初始化不生成运行时代码。
+ 这三个答案，对应三个层次：C 语言的对象模型、工具链的段与符号、单片机的存储介质。

# 第1节|C标准的“五区”
## 1.1标准规定了什么
+ C 标准规定的是：
	+ **对象**（object）:一块能被读写的内存区域，有类型、大小、地址
	+ **存储期**（storage duration）：对象从创建到销毁的时间区间，**活多久**
	+ **作用域**（scope）：标识符在源码的哪些位置可见，**名字在哪可见**
	+ **链接属性**（linkage）：不同翻译单元里的同名标识符是否指向同一个对象，**不同文件里的同名符号是不是同一个对象**
+ 它不规定地址：
	+ 地址空间怎么划分
	+ 栈怎么增长
	+ 堆用什么分配算法
	+ 变量放在Flash，还是RAM
## 1.2”五区“模型
```text
高地址
+---------------------------+
|          栈区 stack        |  局部变量、函数参数、返回地址
|          ↓ 向下生长        |
+---------------------------+
|                           |
|         （空闲区域）        |
|                           |
+---------------------------+
|          ↑ 向上生长         |
|          堆区 heap         |  malloc / free 管理的内存
+---------------------------+
|     未初始化全局区 .bss     |  未初始化或零初始化的全局、static
+---------------------------+
|     已初始化全局区 .data    |  有非零初值的全局、static
+---------------------------+
|        常量区 .rodata      |  字符串字面量、const 全局
+---------------------------+
|        代码区 .text        |  函数体编译后的机器指令
+---------------------------+
低地址
```

## 1.3 语言层-五区与C标准的对应
| 五区  | 对应的标准概念         | 说明             |
| --- | --------------- | -------------- |
| 栈区  | 自动存储期           | 局部变量、函数参数      |
| 堆区  | 动态存储期           | malloc 家族      |
| 全局区 | 静态存储期 + 外部/内部链接 | 全局变量、static 变量 |
| 常量区 | 静态存储期，只读        | 字符串、const 全局   |
| 代码区 | 函数              | 可执行指令          |
## 1.4 工具链层-五区->section

| 区域        | 别名/典型section | 放什么                             | 文件是否有字节 | 占Flash  |
| --------- | ------------ | ------------------------------- | ------- | ------- |
| 栈区        | stack        | 局部变量、函数参数、返回地址、保存的寄存器           | 否       | 否       |
| 堆区        | heap         | malloc / calloc / realloc 返回的内存 | 否       | 否       |
| 全局区（已初始化） | .data        | 有非零初值的全局变量、static 变量            | 是       | 是（初值镜像） |
| 全局区（未初始化） | .bss         | 未初始化或零初始化的全局变量、static 变量        | 否       | 否       |
| 常量区       | .rodata      | 字符串字面量、const 全局变量、查表            | 是       | 是       |
| 代码区       | .text        | 函数的机器指令、中断向量表                   | 是       | 是       |
+ `.bss`**不占用文件体积**，在ELF里它是`SHIT_NOBITS`，只记录大小和运行时的地址，不存字节。加载时在内存里留出空间并清零
	+ **因为它的内容全是零，零不需要存，只需记录地址和大小**；
	+ **加载时由加载器零填充（Linux环境）或启动代码整段清零(裸机MCU)，它仍然占运行时内存**
+ **`.data` 有两个地址。** 运行时地址（VMA）在 SRAM，初值镜像的加载地址（LMA）在 Flash。启动代码负责把初值从 Flash 复制到 SRAM。
## 1.5 芯片层-五区->Flash/SRAM
### STM32F103C8T6 的地址空间：
| 区域    | 起始地址        | 大小   | 放什么                        |
| ----- | ----------- | ---- | -------------------------- |
| Flash | 0x0800_0000 | 64KB | 向量表、.text、.rodata、.data 初值 |
| SRAM  | 0x2000_0000 | 20KB | .data、.bss、heap、stack      |
| 外设    | 0x4000_0000 | —    | GPIO、USART、TIM 等寄存器        |
| 系统存储区 | 0x1FFF_0000 | —    | 出厂 bootloader、选项字节         |
### 五区的物理映射
| 五区          | 住在哪                | 掉电后       | 启动时的动作           |
| ----------- | ------------------ | --------- | ---------------- |
| 代码区 .text   | Flash              | 保留        | 无                |
| 常量区 .rodata | Flash              | 保留        | 无                |
| 全局区 .data   | Flash 初值 + SRAM 变量 | 初值保留，变量丢失 | 从 Flash 复制到 SRAM |
| 全局区 .bss    | SRAM               | 丢失        | 整段清零             |
| 堆区          | SRAM               | 丢失        | 无，等 malloc 来要    |
| 栈区          | SRAM               | 丢失        | 设置初始 MSP         |
## 1.6 注意
+ 五区并不是语言规范，把它当规范，换平台就会出错：
	+ MCU上还可能有`.noinit`[^1]、CCM/TCM[^2]、多块独立RAM[^3]
	+ Linux上有mmap区、vdso
	+ 8051 有 `code`/`data`/`idata`/`xdata` 多个地址空间，指针都要分类型

# 第2节|变量可以活多久
+ 存储期是对象从创建到销毁的时间区间。

| 存储期          | 谁有             | 何时创建   | 何时销毁    | 典型位置         |
| ------------ | -------------- | ------ | ------- | ------------ |
| 静态 static    | 全局变量、static 局部 | 程序启动前  | 程序结束    | .data / .bss |
| 自动 automatic | 普通局部变量         | 进入代码块  | 离开代码块   | 栈，或寄存器       |
| 动态 allocated | malloc 系列      | 调用分配函数 | 调用 free | 堆            |
| 线程 thread    | _Thread_local  | 线程启动   | 线程结束    | TLS 区        |
```c
int g;                  // 静态存储期，零初始化|值是0
void f(void)
{
    int a;              // 自动存储期，初值不确定
    static int b;       // 静态存储期，零初始化
    static int c = 1;   // 静态存储期，初值 1
}
```
+ 注意：
	+ C标准规定静态存储期对象**在程序启动前完成初始化，且只初始化一次**。所以静态变量第二次调用才能保持上一次的值，这是因为它的生命周期贯彻程序始终
	+ 自动变量不初始化就是不确定值，静态变量保持零初始化，这里是启动代码对`.bss`段做了清零







*************
[^1]: `.noinit`:在桌面系统中，`.bss`段会在程序启动时被清零。但是MCU需要在软件复位（如看门狗复位）后保留一些关键变量（如故障记录、重启计数器）
	**链接器行为**：在链接脚本中，该段被标记为 `NOLOAD`，启动代码会跳过对它的初始化
	**效果**：只有**上电复位**时该区域内容才不确定（或为随机值），而**软件复位**后其值会保持。这完全背离了“`bss` 必清零”的桌面模型
[^2]:`CCM/TCM`:这是 MCU 上**性能最高、但也最特殊**的 RAM 区域
	**TCM (Tightly-Coupled Memory)**：ARM 架构标准。直接连接到 CPU 内核，**零等待周期**访问，分为存放指令的 **ITCM** 和存放数据的 **DTCM**。它是存放中断服务程序（ISR）、RTOS 调度器以及**栈**的理想位置，能保证实时性绝对确定。
	**CCM (Core Coupled Memory)**：ST（意法半导体）的实现，概念类似，但通常只作为数据 RAM 使用。
	缺陷：不经过系统总线矩阵，DMA通常无法访问这些区域。数据若要DMA传输，必须先拷贝到主SRAM
[^3]:多块独立RAM:不连续的物理地址
	桌面系统通常只有一条连续的主内存，而MCU的RAM在物理上是碎片化的，可能包含各种内容，这些内容**起始地址不同，大小不同，访问属性也可能不同**。它们无法被塞进一个单一的”堆区“或”栈区“的概念中

# 补充
+ Keil编译结果：`Program Size: Code=3986 RO-data=1958 RW-data=32 ZI-data=1632`
+ 补充一下四个字段的对应

| 字段      | 放什么                 | 占 Flash | 占 RAM | 对应五区               |
| ------- | ------------------- | ------- | ----- | ------------------ |
| Code    | 机器码                 | 是       | 否     | 代码区.text           |
| RO-data | const、字符串、查表        | 是       | 否     | 常量区.rodata         |
| RW-data | 有非零初值的全局/static     | 是（存初值）  | 是     | 全局区.data           |
| ZI-data | 零初始化/未初始化的全局/static | 否       | 是     | 全局区.bss+stack+heap |
+ 所以：
	+ Flash占用=Code+RO-data+RW-data
	+ RAM占用=RW-data+ZI-data

# c->hex
1. 预处理.c->.i
	+ 核心动作：展开 `#include` 的头文件、替换 `#define` 的宏、根据 `#ifdef` 等条件编译指令保留或删除代码块，并移除所有注释
	+ 输入：`.c` 和 `.h` 源文件
	+ 输出：预处理后的 **`.i` 文件**（Intermediate file）。它是一个纯C代码文件，不再包含任何预处理指令，是编译器真正的输入
2. 编译.i->.s
	+ 核心动作：进行词法、语法和语义分析，检查错误，并根据优化选项（如 `-O2`）对代码进行优化，最终生成汇编代码
	+ 输入：`.i`文件
	+ 输出：**`.s` 汇编文件**。这是一个文本文件，包含了该CPU架构对应的汇编指令
3. 汇编.s->.o
	+ 核心动作：将 `.s` 文件中的每条汇编指令转换为对应的机器码（0和1），并生成一个包含代码、数据以及**符号表**的目标文件
	+ 输入：`.s` 文件
	+ 输出：**`.o` 目标文件**（Object file）。每个 `.c` 文件都会生成一个对应的 `.o` 文件。它虽然已经是机器码，但其中的函数和变量地址还是**相对的、未确定的**，因此还不能直接运行
4. 链接.o->`elf`/`alf`
	+ 将所有分散的`.o`文件和库文件“拼接”成一个完整的、地址确定的程序
	+ 核心动作：
	+ 输入：所有 `.o` 文件、库文件、启动文件、链接脚本
	+ 输出：**`.elf`**（在 Keil MDK 中通常为 **`.axf`**）可执行文件。这是一个包含了机器码、调试符号和元数据的复杂文件格式，是用于调试（Debug）的“终极”产物
5. 格式转换.axf->.hex
	 + 核心动作：从 `.elf` 文件中提取出纯二进制数据，并根据烧录需求添加地址和校验信息
	 + 输入：`.elf` 或 `.axf` 文件
	 + 输出：
		 + **`.hex` 文件**：Intel HEX 格式。它是一种带有**地址信息和校验和**的文本文件，非常适合通过串口或调试器烧录到Flash中，是最终交付给生产或用户进行烧录的标准格式
		 + **`.bin` 文件**：纯二进制文件，只包含指令和数据，不包含地址信息。烧录时需要额外指定起始地址
>1. 为什么需要格式转换？
>	`.elf`不是单纯的机器码，它是一个结构化容器，它里面有很多不需要烧进Flash的东西，如果直接把`elf`整个烧进去，Flash里会混入大量调试信息、符号表，既浪费空间，又会让程序布局混乱
>	`.hex`/`.bin` 只保留**需要加载到存储器中的段**，去掉所有调试和元数据
## 其它文件
+ .d：依赖文件
	+ 它是一个文本文件，记录了**某一个源文件（如 `main.c`）在编译时，究竟包含了哪些头文件**。例如，`main.d` 会列出 `main.c` 直接或间接引用的所有 `.h` 文件路径
+ .crf：代码浏览信息库
	+ 它包含了源代码中所有符号（如**宏定义、变量、函数**）的**定义和声明位置**的详细索引信息

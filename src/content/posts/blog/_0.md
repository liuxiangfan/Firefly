# 存储器分类
## 三个维度
| 维度 | 问题 | 两端 |
| --- | --- | --- |
| 易失性 | 掉电后数据还在吗？ | 易失 / 非易失 |
| 可写性 | 运行时能写吗？ | 只读 / 可写（可能有擦除约束） |
| 访问方式 | 能按任意地址访问吗？ | 随机访问 / 顺序、块访问 |
## 常见存储
| 名字     | 是什么       | 干什么用           | 掉电后       |
| ------ | --------- | -------------- | --------- |
| Flash  | 程序存储器     | 放代码、常量、变量的初值   | 不丢        |
| SRAM   | 运行内存      | 放运行时变量、栈、堆     | 丢         |
| EEPROM | 小容量可写存储   | 放参数、校准值、掉电标志   | 不丢        |
| 寄存器    | 内存映射的硬件窗口 | 控制 GPIO、串口、定时器 | 不丢（但值会复位） |
# 命名
## RAM和ROM
+ RAM和ROM是”家族名“，不是具体的器件
+ RAM=Random Access Memory，随机访问存储器。如今含义**可读可写的存储器**
+ ROM=Read-Only Memory，只读存储器。如今含义**掉电不丢失的存储器**
## SRAM
- **SRAM 的 static**：指存储单元不需要刷新，状态能自己保持；
- **C 语言的 static**：指变量的存储期或链接属性。
## Flash
+ Flash 掉电不丢，读起来像 ROM，所以归在 ROM 家族里。但它可以电擦写，所以又不是传统意义上的“只读”。
+ Flash比 RAM 多两条限制：写之前要先擦，而且只能按块擦
# SRAM和Flash的区别
|  | SRAM | Flash |
| --- | --- | --- |
| 掉电 | 丢 | 不丢 |
| 读速度 | 快，通常 1~2 个时钟周期 | 较慢，高频下要插等待周期 |
| 写方式 | 随时写任意字节 | 先擦块，再写；只能把 1 变 0 |
| 擦写寿命 | 无限 | 约 1 万次（看手册） |
| 容量 | 小，KB ~ MB | 大，KB ~ MB（通常比 SRAM 大） |
| 成本 | 贵 | 便宜 |
| 典型用途 | 变量、栈、堆 | 代码、常量 |
+ 程序运行时，CPU 从 Flash 取指令，把需要修改的数据放在 SRAM 里。这就是为什么变量不能直接放在 Flash 里——Flash 改起来太慢、太麻烦，而且有寿命限制
# EEPROM
既然有 Flash，为什么还要 EEPROM？
因为 Flash 改一个字节太麻烦：要先擦一整块，再写回去。而 EEPROM 可以**直接按字节改**。
所以：
- 存代码 → Flash
- 存会变的参数（校准值、设备设置、掉电计数）→ EEPROM
很多 MCU 内部没有 EEPROM，就用 Flash 划一块区域“模拟”EEPROM，本质是用软件换硬件。

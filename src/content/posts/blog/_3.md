>一个最小工程，只有两个全局变量：
>```c
>int ready = 1;        /* 有非零初值 → .data */
  int count;            /* 无初值     → .bss  */
>```
>编译后看三个数字：
>	Program Size：`RW-data` 和 `ZI-data` 各 accounting 了这两个变量；
>	bin 文件大小：只包含 `ready` 的初值，`count` 不在里面；
>	map 文件：
>	.data这一行由两个地址，.bss的Load Addr是空白![image.png](https://photo.070616.xyz/file/1792498516709_image.png)
+ 三个问题:
	1. 为什么 `.bss` 可以不存字节？
	2. `.data` 的两个地址是什么关系，谁在什么时候用它？
	3. 这张地址分配表，是谁定的？
# 从.c到镜像
```text
demo.c → 预处理 → demo.i → 编译 → demo.s → 汇编 → demo.o → 链接 → demo.axf / demo.elf
```
## .o有什么
+ section：按属性分号的数据块。
	+ 代码在.text
	+ 只读数据在 `.rodata`（ARM 编译器还会细分 `.constdata`、`.conststring`）
	+ 已初始化可写数据在 `.data`
	+ 零初始化数据在 `.bss`
+ 符号表：
	+ 每个函数和全局变量的名字
	+ 所属section
	+ 段内偏移、大小
	+ 绑定属性（全局/局部）
+ 此时所有的地址都是段内偏移，没有最终地址。链接器会做三件事：
	1. 合并：把所有.o的同名输入段合并成输出段
	2. 分配地址：按链接脚本给每一个输出段指定区域和地址
	3. 重定位：把代码里所有引用符号的地方改成绝对地址；没有解析的符号在这一步报undefined reference
### 解释
假设有两个文件：
```c
/* a.c */
int g = 1;
int get_g(void) { return g; }
```
```c
/* main.c */
int get_g(void);
int main(void) { return get_g(); }
```
汇编后的a.o内部大概是：
```text
a.o
├── .text 段：get_g 的机器码
├── .data 段：g 的 4 字节初值 01 00 00 00
├── 符号表
│     g       → 定义在本 .o，属于 .data，偏移 0
│     get_g   → 定义在本 .o，属于 .text，偏移 0
└── 重定位表
      .text 里有一条记录："引用了 g，地址待定"
```
+ 所有地址都是相对于本文件内section起点的偏移，比如g就是`.data+0`
+ `.text` 里凡是要用到别的符号的地方，*汇编器***留一个占位值**（通常是 0），同时在重定位表里登记一条记录：“这个位置最终要填 `g` 的地址，填法见重定位类型”
+ 符号分三种状态：**定义**（本文件提供）、**未定义**（`main.o` 里的 `get_g`，本文件只引用不提供）、**局部/全局**（`static` 决定）
+ 总结：`.o` 是一份“半成品 + 一张待办清单”。链接器的工作就是按清单把所有占位值填成真地址
### 合并-本质是符号解析
+ 链接器把所有`.o`和库扫一遍，建立一张全局符号表，把每个符号跟它的定义对应
+ **`static` 的作用**：`static` 变量只进各文件的局部符号表，不进全局符号表。所以同名的static定义不冲突
### 分配地址-查链接脚本
+ 合并只得到”段有多长“，还没有绝对地址。
+ 链接器按照链接脚本为输出段指定地址
```text
//链接脚本
.flash (0x08000000) : { 向量表, .text, .rodata, .data 的 LMA }
.ram   (0x20000000) : { .data 的 VMA, .bss, heap, stack }
```
### 重定位-按清单回填
+ 按照重定位表，逐条处理
```text
//每一条记录包含四条信息
【哪个文件】【哪个 section 的第几个字节】【引用了哪个符号】【用什么公式计算】
//公式就是重定位类型，怎么计算绝对地址
```
## 镜像
+ 链接完的产物叫做镜像（image），也就是.axf/.elf
+ bin/hex是从镜像中提取“需要加载的内容”得到的子集
# 镜像的结构
ARM的镜像按三层组织
```text
Load Region（加载域）
  Execution Region（执行域）
    Section（输出段）
```
每个执行域有两套地址：
+ 加载地址（LMA）：程序烧录后，这段内容在哪。MCU上就是Flash
+ 执行地址（VMA）：程序运行时，这段内容应该在哪个地址被访问。
多数情况下，二者相同：`.text`、`.rodata` 烧在 Flash、也在 Flash 执行，LMA = VMA。
## 例外：.data
+ 有时候变量需要同时满足这两个要求：
	+ 初值必须掉电不丢失->存Flash(LMA)
	+ 变量必须可写->循行时在SRAM(VMA)
+ 于是.data段在镜像里出现两次：Flash里一份初值镜像，SRAM里一份运行时空间。这里是指地址空间里给它留了两个位置，并不是文件里存了两份
## 特殊：.bss
+ .bss初值全是0，搬运若干个0没有意义，所以只在SRAM里留空间，启动时整段清零，Flash里什么都不存
+ 对应VMA(Exec Addr)有地址，LMA(Load Addr)无地址
# 启动文件
STM32 标准启动文件（`startup_stm32f10x_md.s`）的 `Reset_Handler`：
```asm
Reset_Handler    PROC
                 EXPORT  Reset_Handler             [WEAK]
                 IMPORT  __main
                 IMPORT  SystemInit
                 LDR     R0, =SystemInit
                 BLX     R0
                 LDR     R0, =__main
                 BX      R0
                 ENDP
```
真正干活的是C库的`_main`,它分两步：
1. `__scatterload`：按链接器生成的散列表（region table），把 `.data` 从 Flash 复制到 SRAM，把 `.bss` 清零；
2. `__rt_entry`：调用 `__rt_libinit`（初始化 C 库、执行 `.init_array`），然后调用 `main`

# 链接脚本
**Keil** 默认不让你直接写脚本，它根据 Options → Target 里的 IROM1/IRAM1 生成 scatter file（`Objects\<工程名>.sct`）：
```text
/*
*一个 64KB 的 Flash 加载域，里面包含一个 Flash 执行域（代码/只读）和一个 RAM 执行域（RW/ZI）；RW 的初值映像仍然放在 Flash 加载域里，运行时搬到 RAM
*/
LR_IROM1 0x08000000 0x00010000  {//定义一个名字为LR_IROM1的加载域，LMA=0x08000000
  ER_IROM1 0x08000000 0x00010000  {//定义一个名字为ER_IROM1的执行域，VMA=0x08000000,Flash。这些只读内容运行时就在 Flash 的 0x08000000 处被取指/读取
    //*.o：所有目标文件
    //(RESET, +First)：把名字为 RESET 的输入段收集进来，并放在本执行域的最前面
    //作用：保证向量表位于0x08000000
    *.o (RESET, +First)
    
    //选择所有目标文件中名为 InRoot$$Sections的输入段
    //作用：把 C 库启动所需的根段固定在 Flash 执行域中
    *(InRoot$$Sections)
    
    //.ANY:链接器按照属性自动把剩余匹配的输入段分配进来
    //+RO：只读属性
    //所有没被前面规则显式选走的只读内容，都放进 `ER_IROM1`，即 Flash，就地执行/读取
    .ANY (+RO)
  }
  RW_IRAM1 0x20000000 0x00005000  {//定义一个名字为RW_IRAM1的执行域，VMA=0x20000000,SRAM。所有可读写和零初始化变量，运行时住在 RAM 的 0x20000000 起、最多 20KB 范围内
    .ANY (+RW +ZI)
  }
}
```
+ LR_IROM1:加载域，Flash从0x0800000起，共64KB
+ ER_IROM1:执行域，`+RO`（代码和只读数据）都放在这里，LMA=VMA
+ RW_IRAM1:执行域：`+RW +ZI`放SRAM
+ `.ANY`表示“没被前面规则选中的段都放在这
+ `RW_IRAM1` 虽然是 RAM 执行域，但它**嵌套在 `LR_IROM1` 里**，所以它的加载映像（`.data` 初值）会被链接器安排在 Flash 的 `LR_IROM1` 范围内，启动时由库代码复制到 RAM
